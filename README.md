# Wc3Transfer — утилита переноса между картами Warcraft 3

Набор Python-скриптов для переноса объектов, кода (JASS), ассетов и геометрии
между картами WC3 в **lni-формате** (распакованные [w3x2lni]), а также
обслуживания одной карты без карты-донора: чистка объектов и триггеров,
починка ini-таблиц, деобфускация JASS, конвертер равкодов.

> ⚠️ Инструмент для собственных карт и модов. Работает с распакованными
> lni-папками, а не с сырыми `.w3x` — сначала распакуйте карту w3x2lni.

## Возможности

**Перенос (донор → приёмник), этапы пайплайна:**

- **registry** — реестр занятых ID приёмника + дубли имён
- **mapping** — сопоставление ID донор→приёмник (режимы `smart` / `replace_std` / `custom_only`)
- **deps** — граф зависимостей от корней: способности → баффы → эффекты/иконки → предметы
- **tables** — перенос секций `[ID]` ini-таблиц (unit/ability/buff/item/upgrade) с новыми ID
- **import** — копирование ассетов (resource/sound) с переименованием конфликтов
- **code** — перенос папок триггеров донора с заменой литералов `'Xyyy'` по маппингу; раскладка на выбор: «Одна папка» (всё в `deploy_to`) или «Папки как у донора» (каждая папка донора — своя папка в редакторе триггеров);
- **code_cut** — вырезка функций героя из монолита `war3map.j` (BFS по вызовам)
- **globals** — перенос блока `globals` из `war3map.j` донора
- **geometry** — вставка декора/юнитов в `war3map.doo` / `Units.doo` со смещением
- **testspawn** — генерация TestSpawn-триггера для проверки перенесённого в игре
- **verify** — проверка приёмника: секции, регистр-конфликты, ссылки, ассеты, баланс скобок

**Обслуживание одной карты (без донора):**

- `stage_cleanup.py` — чистка объектов карты (удаление только по подтверждённому списку), `stage_repair.py` — починка ini-таблиц
- `stage_triggers.py` — чистка триггеров: пустые папки, Disab/Closed, мёртвые функции (каскад)
- `deob1.py` / `deob2.py` — деобфускация JASS с переименованием идентификаторов
- `stage_rawconv.py` — конвертер равкодов (`0x...` → `'RAWC'`, десятичные и `$`-литералы)
- `stage_verify.py` — верификация приёмника

## Установка

```bash
# Python 3.10+
pip install -r requirements.txt      # единственная зависимость: customtkinter
```

## Быстрый старт

**1. Распакуйте обе карты** w3x2lni в lni-папки.

**2. Заполните `transfer_config.json`** — единственный конфиг. Важно:

- `source` / `target` — пути к lni-папкам донора и приёмника (прямые слэши: `C:/...`);
- `mapping.prebuilt_dir` — **обязателен**: папка `prebuilt\Custom` из комплекта
  w3x2lni вашей версии патча (источник истины «что стандарт»);
- строки-пути в выложенном конфиге — под машину автора, перебейте под свои;
- несколько пар карт = несколько копий конфига (`--config X.json`).

**3. Запуск:**

```bash
python transfer_run.py --plan        # показать план
python transfer_run.py --dry-run     # весь пайплайн без записи — ВСЕГДА первым
python transfer_run.py --all         # весь пайплайн (докатка: пройденное пропускается)
python transfer_run.py --stage code  # один этап
python transfer_run.py --loop        # цикл с авто-расширением deps
python transfer_run.py --remap       # пересчёт registry+mapping под пару карт
python transfer_run.py --rollback    # откат к бэкапу последнего успешного этапа
python transfer_run.py --status
```

**GUI:** `Утилита переноса.bat` (или `python transfer_gui_ctk.py`).
Два режима: «Перенос» (полный пайплайн) и «Обслуживание» (одна карта без донора).

## Безопасность

- **State + снапшоты + манифест**: прогресс привязан к паре карт (`transfer_state.json`),
  перед каждым этапом изменяемые файлы приёмника копируются в `transfer_backup/`,
  всё записанное утилитой фиксируется в `deploy_manifest.json` (повторный прогон
  чистит за собой старое). `--rollback` откатывает.
- **Железные правила** (нарушение ломало карту) — полный список в
  [`DEVELOPMENT.md`](DEVELOPMENT.md), §8. Кратко:

  1. Каталог и триггеры приёмника НЕ сканировать: LML-файлы записывать только под своим префиксом (`deploy_to`).
  2. При любом сбое сносить `deploy_manifest.json` перед повторным запуском.
  3. Полный прогон на свежей копии — ВСЕ этапы, не только `code + globals`.
  4. `prebuilt_dir` обязателен — без него тысячи ложных «битых _parent».
  5. Dry-run перед любой записью («боевой» галочка dry-run снимается).
  6. Удаления — только по подтверждённому списку через GUI.
  7. B-литералы (баффы) — только с явным `allow_b`.
