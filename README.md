# Wc3Transfer: утилита переноса и обслуживания карт Warcraft 3

Инструмент для работы с картами WC3 в **lni-формате** (распакованный
[w3x2lni]): перенос объектов, триггерного кода (JASS), ассетов и геометрии
из карты-источника в карту-приёмник, а также обслуживание отдельной карты
без донора: чистка объектов и триггеров, починка ini-таблиц, проверка
целостности, деобфускация JASS, конвертер равкодов.

Утилита работает с распакованными папками lni, не с сырыми файлами
`.w3x`. Карту сначала нужно распаковать w3x2lni.

## Возможности

### Перенос (донор, приёмник)

Пайплайн из этапов, порядок фиксирован:

| Этап | Назначение |
|---|---|
| `registry` | реестр занятых ID приёмника, дубли имён |
| `mapping` | сопоставление ID донор → приёмник; режимы `smart`, `replace_std`, `custom_only` |
| `deps` | граф зависимостей от корней: `_parent`-родители, способности, баффы, эффекты, иконки, предметы; пустые корни = ПОЛНЫЙ перенос всех секций (+ ассеты resource/sound) |
| `tables` | перенос секций ini-таблиц (unit/ability/buff/item/upgrade) с новыми ID |
| `import` | копирование ассетов (resource/sound) по deps; конфликты имён — md5-сравнение (одинаковый контент = пропуск, разный = `_vN` рядом); «игровые» пути (Abilities/Units/ReplaceableTextures) при выключенном перехвате тоже идут `_vN`-рядом, а не пропускаются; renames применяются к таблицам в том же прогоне |
| `code` | перенос папок триггеров донора с заменой литералов `'Xyyy'` по маппингу; раскладка «одна папка» или «папки как у донора» |
| `code_cut` | вырезка функций из монолита `war3map.j` донора (BFS по вызовам) |
| `globals` | перенос блока `globals` из `war3map.j` донора |
| `geometry` | вставка декорации и юнитов в `war3map.doo` / `Units.doo` со смещением; опционально рельеф w3e (`geometry.w3e.enabled`) |
| `testspawn` | генерация триггера спавна перенесённых героев для проверки в игре |
| `verify` | проверка приёмника: секции, конфликты регистров, ссылки, ассеты (включая контент-конфликты по md5), баланс скобок, донорские хвосты в lml/.j (равкоды и hex), дубли imp.ini |

### Обслуживание отдельной карты

- чистка объектов карты: удаление только по подтверждённому списку,
  с резервными копиями и журналом;
- чистка триггеров: пустые папки, отключённые и закрытые триггеры,
  неиспользуемые глобалки, мёртвые функции с каскадным обходом;
  список наполняется прямо в графическом окне по ходу скана;
- починка ini-таблиц: разбаланс `[=[ ]=]`, дубли секций, битые `_parent`;
- верификация карты без записи;
- деобфускация JASS: переименование идентификаторов, восстановление
  форматирования, отчёт VERIFY с проверкой эквивалентности;
- конвертер равкодов `0xXXXXXXXX` и десятичных литералов в `'RAWC'`;

### Общий сервис

- снимки изменяемых файлов перед каждым этапом, журнал записанного
  (манифест деплоя), откат последнего успешного этапа;
- состояние прогона привязано к паре карт, повторный запуск докатывается
  без повторной работы;
- настраиваемый лимит времени этапа (`safety.stage_timeout_min`, 0 без лимита);
- журналы и резервные каталоги операций обслуживания назначаются в конфиге
  (`cleanup.*`, `trigclean.*`, `repair.*`, `rawconv.backup_dir`).

## Интерфейс

GUI на [CustomTkinter]: вкладки «Перенос», «Обслуживание», «Журнал»;
светлая и тёмная тема; выбор путей с историей последних значений;
горячие клавиши Ctrl+1/2/3 (вкладки) и Ctrl+S (сохранение конфига).
Все настройки пайплайна и операций обслуживания задаются в интерфейсе
и хранятся в JSON-конфиге.

## Установка

Python 3.10 и новее. Единственная зависимость:

```bash
pip install -r requirements.txt
```

## Начало работы

1. Распакуйте карты w3x2lni в папки lni.
2. Заполните `transfer_config.json`:
   - `source` и `target`: пути к папкам донора и приёмника (прямые слэши);
   - `mapping.prebuilt_dir`: обязательный путь к папке `prebuilt\Custom`
     из комплекта w3x2lni вашей версии патча, источник истины о стандарте;
   - несколько пар карт разводятся отдельными копиями конфига
     (`--config имя.json`).
3. Прогон:

```bash
python transfer_run.py --plan        # показать план без изменений
python transfer_run.py --dry-run     # весь пайплайн без записи, всегда первым
python transfer_run.py --all         # боевой прогон, докатка
python transfer_run.py --stage code  # один этап
python transfer_run.py --loop        # цикл с автоматическим расширением deps
python transfer_run.py --remap       # пересчёт реестра и маппинга под пару карт
python transfer_run.py --rollback    # откат к снимку последнего этапа
python transfer_run.py --status      # состояние прогресса
```

Смена набора переноса (include/roots) после того, как прогон уже
выполнялся: mapping читает `deps_result.json`, обновлённый deps только
в конце своего этапа. После правки набора запустите `--reset`, затем
`--stage mapping`, затем `--all` — иначе tables может получить старый
список объектов. Это же делает `--remap`.

GUI: `python transfer_gui_ctk.py` либо лаунчер `.bat`.

## Безопасность

Изменяемые файлы приёмника копируются в резервные каталоги перед каждым
этапом; всё записанное утилитой фиксируется в манифесте и чистится при
повторных прогонах; удаление объектов и триггеров выполняется только по
подтверждённому пользователем списку. Полный перечень правил работы и
наблюдение из практики: [`DEVELOPMENT.md`](DEVELOPMENT.md).

## Ограничения

- проверка кода собственная (секции, ссылки, скобки), компиляторной
  проверки pjass нет;
- повторный запуск геометрии безопасен: вставки с теми же (id, x, y)
  пропускаются;
- ландшафт (w3e): экспериментальная вставка со смещением
  (`geometry.w3e.enabled`); на картах, где заголовок w3e не удаётся
  разобрать, этап пропускается с диагностикой, файл не трогается;
- сборка в автономный исполняемый файл не подготовлена.
