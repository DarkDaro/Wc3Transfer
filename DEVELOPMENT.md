# Wc3Transfer: документация для разработчика

Назначение: перенос объектов, кода, ассетов и геометрии между картами WC3
в lni-формате (распакованные w3x2lni), плюс обслуживание одной карты
без карты-донора. Пользовательская часть: [README.md](README.md).

## 1. Общая архитектура

```
transfer_run.py        : CLI-оркестратор, запускает stage_*.py по очереди,
                         ведёт state (докатка), снапшоты, rollback
transfer_config.json   : единственный конфиг (правится руками или из GUI)
stage_<имя>.py         : этапы пайплайна, каждый читает конфиг сам;
                         sys.argv[1] = путь к конфигу, флаг --dry-run
transfer_gui_ctk.py    : GUI (CustomTkinter), обёртка над тем же пайплайном
deploy_manifest.py     : модуль манифеста деплоя (что утилита записала в приёмник)
```

Рабочие файлы (state, mapping, registry, манифест, логи) живут рядом с конфигом
(`cfg_dir()`), поэтому несколько пар карт оформляются несколькими конфигами
и не перекрываются.

## 2. Запуск

### CLI

```
python transfer_run.py --plan        # показать план (карты, этапы, таблицы)
python transfer_run.py --dry-run     # весь пайплайн без записи
python transfer_run.py --all         # весь пайплайн (докатка: пройденные этапы пропускаются)
python transfer_run.py --stage code  # один этап
python transfer_run.py --loop        # цикл deps->mapping->tables->import->code->globals->code_cut
                                     #   с повторами, пока auto_expand добавляет deps (макс 5 итераций)
python transfer_run.py --remap       # пересчёт registry+mapping под текущую пару карт
python transfer_run.py --rollback    # откат к бэкапу последнего успешного этапа
python transfer_run.py --status      # состояние
python transfer_run.py --reset       # сброс прогресса для текущей пары
python transfer_run.py --config X.json   # другой конфиг (другая пара карт)
```

### GUI

`transfer_gui_ctk.py` (или лаунчер `.bat`). Интерфейс построен на вкладках
(`CTkTabview`), режим структуры синхронизирован с вкладками:

- **Перенос**: полный пайплайн донор к приёмнику. Две скроллируемые колонки:
  слева этапы с галочками и опции (dry-run, раскладка кода, лимит этапа),
  справа карточки настроек (карты, таблицы, код, geometry, testspawn, линии
  конфига) и блок команд. Карточка «Пути и лимиты (Обслуживание)»
  настраивает каталоги журналов и бэкапов сервисных операций.
- **Обслуживание**: работа с одной картой (приёмником) без донора:
  верификация, чистка объектов, чистка триггеров, починка таблиц,
  деобфускация, конвертер равкодов, манифест, TestSpawn. В этом режиме
  поля донора заблокированы.
- **Журнал**: полный лог с поиском, режим не переключает.

Подробности: тема light/dark, история путей (кнопка «~» у полей, до 10
значений, ключи `gui.path_history`), горячие клавиши Ctrl+1/2/3 (вкладки)
и Ctrl+S (сохранение конфига), звук по завершении, авто-открытие лога,
прогресс-бар по этапам (оркестратор пишет `=== ЭТАПЫ: N`).

## 3. Профили и этапы

Профиль в конфиге (`profile`) задаёт набор этапов:
`heroes`, `objects`, `items`, `full`, `custom` (по секции `stage_enabled`).

Полный список этапов (порядок важен):

| Этап | Что делает | Выход |
|---|---|---|
| `registry` | реестр занятых ID приёмника + дубли имён | `target_id_registry.json` |
| `mapping` | сопоставление ID донор к приёмник; режимы `smart` / `replace_std` / `custom_only`; классификация «стандарт/кастом» по prebuilt приёмника | `transfer_mapping.json` + `.pkl` + `mapping_report.txt` |
| `deps` | граф зависимостей от корней (`deps.roots`): способности, баффы, эффекты/иконки, предметы | `deps_result.json` |
| `tables` | перенос секций `[ID]` ini-таблиц с новыми ID; `_parent` мапится, равкоды в abilList/buffList заменяются | `table/*.ini` приёмника |
| `import` | копирование ассетов (resource/sound): нет, копировать; байт-в-байт, пропуск; конфликт, `<имя>_v2` + подмена пути | файлы приёмника + `assets_renamed` в deps_result |
| `code` | перенос папок триггеров донора (`deploy_to`) с заменой литералов `'Xyyy'` по маппингу; шапка донора (header append); обновление catalog.lml; null-конверт битых gg_unit. Раскладка `code.folders`: `flat` означает всё в `<entry>` (папка донора становится префиксом имени файла), `folders` означает раскладку по папкам верхнего уровня `trigger\` (редактор не умеет вложенность, но поддерживает несколько папок верхнего уровня; чужие/вложенные имена дают предупреждение): `trigger/<folder>/*.j` | `trigger/<deploy_to>/*.j`, `code.j`, `catalog.lml` |
| `code_cut` | вырезка функций героя из монолита war3map.j донора (BFS по вызовам), для карт без исходника; опция `auto_expand` | `cut_heroes.j` + отчёт |
| `globals` | перенос блока globals из war3map.j донора; `gg_*` выкидываются; имя+тип совпали означает пропуск, тип разный означает блокировку | `<entry>-Globals.j` + catalog.lml |
| `geometry` | вставка декора/юнитов в war3map.doo/Units.doo со смещением; авто-подбор по воде если offset=null | `map/*.doo` |
| `testspawn` | генерация TestSpawn .j: спавн перенесённых героев/предметов сеткой (20/ряд) для проверки в игре | `90-TestSpawn.j` |
| `verify` | проверка приёмника: секции на месте, регистр-конфликты, ссылки abilList/buffList, ассеты на диске, баланс скобок | отчёт; ошибки валят этап |

B-литералы (баффы `'Bxxx'`) в этапе code заменяются только с подтверждением:
флаг `code.allow_b` в конфиге или `--allow-b` в CLI.

## 4. Безопасность (state, снапшоты, манифест)

- **State** (`transfer_state.json`): привязан к паре карт (`source->target`).
  Смена пары выполняет автоматический сброс completed. `--reset` выполняет ручной сброс.
- **Снапшоты**: перед каждым этапом изменяемые файлы приёмника копируются в
  `transfer_backup/<этап>/`. `--rollback` восстанавливает последний успешный.
- **Манифест** (`deploy_manifest.json`, модуль `deploy_manifest.py`): какие
  файлы/записи каталога записала утилита. Решает проблему «поколений»:
  повторный прогон или смена deploy_to чистит за собой старое по манифесту.
  Сверка «наше vs чужое» выполняется только по манифесту.
- У каждого этапа есть защитный лимит времени `safety.stage_timeout_min`
  (минуты, 0 означает без лимита; значение по умолчанию настраивается в
  конфиге и в GUI). Лимит защищает от зависания процесса этапа
  (антивирусные задержки на старте python); время этапа пишется в лог.

## 5. Инструменты обслуживания (без донора)

| Скрипт | Назначение |
|---|---|
| `stage_cleanup.py` | чистка объектов карты: `--scan` даёт `cleanup_scan.json`; удаление только по подтверждённому списку из GUI, с бэкапом. Никаких молчаливых удалений |
| `stage_repair.py` | починка `table/*.ini`: разбаланс `[=[ ]=]`, дубли секций, оборванные секции, битый `_parent`, с восстановлением на дефолтного родителя типа |
| `stage_triggers.py` | чистка триггеров: пустые папки, Disab/Closed (с проверкой использования функций), неиспользуемые глобалки variable.lml, мёртвые функции (каскад). НЕ трогает war3map.j и code.txt |
| `stage_verify.py` | верификация приёмника (тот же, что этап verify) |
| `deob1.py` / `deob2.py` | деобфускация JASS: переформатирование + переименование идентификаторов по типу/семантике + проверка эквивалентности токен-стрима. Выход `<имя>_deobfuscated.j` + `rename_map.csv` |
| `stage_rawconv.py` | конвертер равкодов в .j: `0x...` даёт `'RAWC'`, десятичные обфусцированные (1097691750 даёт 'Amrf'), `$`-литералы JASS ($D000F даёт 'RAWC' или десятичное). Фильтр: только печатаемые ASCII-байты. Скан/конверт с бэкапом |
| `make_manifest.py`, `list_parens.py`, `peek_bat.py` | мелкие утилиты |

Файлы `_diag_*.py`, `_patch_*.py`, `_t_*.py`, `t_*.j`, `_deob*_map.csv` являются
одноразовыми диагностическими/патчевыми скриптами прошлых сессий и синтетическими
тестами (`_t_parsers.py`, `_t_gg_null.py`, `_t_w3e.py`, `_t_flags.py`,
`_t_tsp_center.py`). Не часть пайплайна; трогать не нужно.

`transfer_backup/` хранит снапшоты этапов (по датам), `logs/transfer.log`
представляет журнал.

## 6. Конфиг transfer_config.json: шпаргалка

Ключевые секции:

- `source` / `target` / `name`: пара карт и подпись;
- `tables` / `skip_tables`: какие ini переносим (unit/ability/buff/item/upgrade),
  w3i и misc не трогаем;
- `tables_update_existing`: обновлять существующие секции приёмника, а не
  только добавлять новые;
- `import`: copy_dirs (resource/sound), exclude_paths (UI, loadingscreen,
  minimap и т.п.), check_missing_refs, allow_override;
- `code`: deploy_to (имя папки триггеров в приёмнике), folders (раскладка
  flat/folders), include_monolith, allow_b, only_dirs, header_mode (append),
  func_prefix, update_catalog, null_broken_ggunit;
- `geometry`: enabled, offset [dx,dy], recount_z;
- `testspawn`: enabled, heroes (пусто означает все из deps), items, rect;
- `mapping`: mode (smart/replace_std/custom_only), prebuilt_dir (обязательно
  задавать: источник истины «что стандарт»), case_conflict_check,
  duplicate_name_check;
- `deps.roots`: ID героев/предметов, от которых строится граф;
- `selection.file`: путь к набору выборочного переноса (22.10).
  Пусто = `<имя конфига>_set.json` рядом с конфигом. Формат: списки
  `include` (вливается в deps.roots), `exclude_objects` (вычёркивается
  из закрытого графа), `exclude_triggers` (пропуск/файлов кода донора,
  .j и .lml-пары; code-split не фильтруется). Пример:
  `transfer_set.example.json`. Файл в .gitignore (личные выборки);
- `code_cut`: entries (точки входа), auto_expand;
- `safety`: backup_dir, state_file, dry_run_first, stop_on_error,
  stage_timeout_min (лимит этапа, минуты, 0 означает без лимита);
- `cleanup`: log_dir, backup_dir (каталоги журналов и бэкапов чистки объектов);
- `trigclean`: log_dir, backup_dir (аналогично для чистки триггеров);
- `repair`: log_dir, backup_dir (аналогично для починки ini);
- `rawconv`: backup_dir (каталог бэкапов конвертера равкодов);
- `profile` + `stage_enabled`: какие этапы включены;
- `gui`: тема, звук, лог, путь_история.

Пустое значение пути в GUI убирает ключ из конфига, и этап берёт дефолт
(каталог `logs/` и `transfer_backup/` рядом с конфигом).

## 7. Проверенный порядок работы (боевой)

1. Заполнить конфиг под пару карт (`--config`, если пар несколько).
2. `--remap` (registry + mapping под текущую пару).
3. `--dry-run`: всегда первым (verify в dry-run пропускается автоматически).
4. `--loop`: полный цикл с авто-расширением deps.
5. `--stage verify` (или «Верификация» в GUI): 0 ошибок.
6. Сборка карты w3x2lni + тест в игре.

Повторный `--all` после прогона проходит «уже пройдено» за секунды, это норма
(докатка идемпотентна).

## 8. Основные правила (нарушение ломало карту)

1. **Каталог и триггеры приёмника НЕ сканировать.** Автодописка catalog.lml
   по папкам приёмника однажды вписала 1938 строк мусора: отключённые
   триггеры «включились» (флаги Disab/Closed/Comment живут под записью),
   сотни пустых триггеров, карта развалилась. Сканер вырезан из
   stage_code.py навсегда. Писать в catalog.lml нужно только свои записи
   (разделитель deploy_to + свои файлы).
2. **Манифест: временный артефакт.** При любом сбое удалять
   deploy_manifest.json перед повторным запуском. Stale-манифест + свежая
   копия приёмника создают риск purge родных записей (если карты от одного
   оригинала, совпадающие ID-имена). После замены trigger/ на свежую копию
   старый манифест удалять.
3. **Полный прогон на свежей копии означает ВСЕ этапы**, не только
   code+globals (иначе 1000+ ошибок verify).
4. **prebuilt_dir в конфиге обязателен** (иначе тысячи ложных «БИТЫЙ _PARENT»).
5. **Dry-run перед записью.** Галочка «сухой пробег» в GUI должна быть снята
   перед боевым прогоном.
6. **Удаление выполняется только по подтверждённому списку** (cleanup/trigclean):
   скан, затем JSON, подтверждение человека, удаление с бэкапом.
7. **B-литералы** (баффы) заменяются только с явного разрешения (allow_b).
8. **Геометрия: редко**: с 22.10 есть защита от повторов (дедупликация
    вставок декора/юнитов по идентичным (id, x, y) в приёмнике).

  несовпадении тайлсетов), но на живой паре BVO3.2/LOWSTOBVO (w3e вер. 11)

  зон не сходятся с классической схемой `magic+ver+NG+NC+Mx+My+центр`.
  Ни одна схема разбора (с пропусками или без) длину массива клеток
  не подтвердила, поэтому этап мягко отказывается с диагностикой
  (файл приёмника не трогается). Для продолжения нужен честный реверс
  заголовка ver 11 на этой паре. До 22.10 старый `read_w3e_heights`
  считал заголовок по off=16 и на такой карте молча возвращал
  Mx=My=0 (пустые высоты, вставкам ставился z=0): теперь высоты либо
  честные, либо этап явно пишет «высоты недоступны» и берёт z из донора.
- **Расширение null-конверта gg_unit** на родные lni-файлы приёмника
  (наблюдение с конкретной карты: десятки битых ссылок на юниты).
- **Сборка в единый .exe** (PyInstaller, `--onefile --windowed`,
  `--collect-all customtkinter`, конфиг рядом с exe). Запланировано после
  стабилизации.
- **Финальная чистка Comment-заглушек** на тестовой карте: галочка чистки
  теперь безопасна, но контрольный прогон не завершён.
- Тесты: есть синтетические (`_t_*.py`) и GUI-автотесты, нет регрессионного
  прогона всего пайплайна на тестовой паре карт одной командой.

## 10. Известные грабли (коротко)

- stage_code: папка приёмника под GUI-пару (.lml) создаётся до записи
  (22.10): без makedirs этап падал на новой папке донора после
  копирования .j, до каталога и манифеста — «триггеры частично
  перенеслись».
- stage_code: префиксация функций — один проход по идентификаторам
  (22.10). Не возвращать цикл из 4 regex на каждое имя донора: это
  десятки млн regex-операций (этап был 800+ сек, стал ~11 сек).
- PowerShell ломает UTF-8 с кириллицей: чтение файлов выполняется только
  Python (encoding='utf-8'), команды `type` / `Get-Content` для .md/.lml
  с кириллицей не использовать.
- Пути конфига записываются с прямыми слэшами (`C:/...`).
- GUI и CLI синхронизированы по конфигу: новая опция появляется и в конфиге,
  и в GUI (правило конфиг-UI: контрол + `_collect_cfg` + `_load_cfg`).
- Оркестратор логирует построчно; GUI читает лог через очередь (threading).
  При добавлении вывода в stage-скрипты формат `=== ЭТАПЫ: N` трогать
  нельзя (прогресс-бар его парсит).
- Комментарии в коде ставятся с датой (`# ДД.ММ:`), конвенция проекта.
- 20.10: `stage_code.py` пишет ключи каталога без кавычек (`213-LIA:`),
  при этом regex `entry_name` допускает оба вида (латентный «переезд» записи
  из `<NNN-dep>` в `<dep>` при повторных прогонах исправлен дым-тестом).
  В live-каталогах редактора ключи кавыченные: оба вида читаются.
