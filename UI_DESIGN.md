# UI-стандарт: дизайн и улучшения GUI (методичка для переноса)

Документ описывает прикладные решения интерфейса, выработанные в
Wc3Transfer, для повторного использования в других приложениях на
CustomTkinter. Все решения проверены автотестами и в работе.

## 1. Структура окна

- Главное окно строится на вкладках `CTkTabview`, а не на смене рамок:
  отдельно «основной режим», «инструменты», «журнал». Вкладка «Журнал»
  не переключает логику, только просмотр.
- Сегмент режима (`CTkSegmentedButton`) остаётся в шапке и синхронизируется
  с вкладками двумя функциями:
  - выбор вкладки -> сегмент + применение режима (`_on_tab`);
  - выбор сегмента -> вкладка + применение режима (`_apply_mode`).
- Взаимные циклы сегмент/вкладки гасятся флагом-защитой `_tab_guard`:
  программный `tabview.set` НЕ вызывает `command` сегмента, поэтому
  после программного переключения вызов `_apply_mode()` выполняется явно.
- Восстановление состояния: режим сохраняется в конфиг (`ui.mode`)
  и применяется после первой отрисовки окна через `after(300)`:
  configure до рендера ломает pack-геометрию (окно 200x200, кнопки
  мёртвые).
- Геометрия окна сохраняется в конфиг и восстанавливается с защитой
  от выхода за экран; `minsize` единый везде (не меньше минимальной
  рабочей раскладки).

## 2. Шапка и статус

- Шапка: название, приглушённая подпись (мелкий серый шрифт), индикатор
  режима справа, сегмент темы, акцентная полоса 2px под шапкой.
- Статусбар ставится над вкладками (не в подвале): на маленьких окнах
  не исчезает.
- Статус пульса: во время долгой операции статус пишет «этап X идёт
  N сек...» по тикам из вывода процесса, так что окно выглядит живым
  при остановленном прогресс-баре.

## 3. Компоновка кнопок

- Кнопки собираются в смысловые строки с фиксированной шириной:
  первая строка «подготовка» (сохранить/план/dry-run/пересчёт),
  вторая строка «боевые команды» (запуск красным шире, цикл зелёным,
  статус/откат/сброс нейтральными), затем донорные под-операции.
- Рабочие кнопки инструментов: сетка по группам с заголовками групп,
  фиксированная ширина (215, 235), одинаковая высота.
- Семантика цвета: red/danger, зелёный/ok, warn/оранжевый акцент;
  безопасные операции (проверки без записи) всегда зелёные.
- Уведомления вместо модалок: тосты справа снизу стопкой, звук опционален;
  блокировка групп кнопок на время операции.

## 4. Поля ввода и пути

- Поле + кнопка «...» (выбор каталога) + кнопка «▾» (история до 10
  значений, хранение в конфиге `gui.path_history`; свежие сверху,
  дубли поднимаются). История привязана к смыслу поля отдельным ключом
  (`map`, `src`, `j`).
- Правый клик в поле: «Вставить из буфера» с чисткой кавычек
  (проводник копирует путь в кавычках).
- Пути-настройки с семантикой «пусто = по умолчанию»: пустое поле
  удаляет ключ из конфига, и этап берёт дефолт рядом с конфигом.
  Подпись-подсказка прямо в карточке: «Пусто = путь по умолчанию».

## 5. Конкурентный доступ и поток вывода

- Весь вывод subprocess через очередь `queue.Queue`, Tk читает её
  по `after(100)`, никогда напрямую из потока.
- Формат служебных сообщений процесса: `@@PROGRESS n/m`, `@@STAGE имя`,
  `@@TICK сек`: GUI парсит их в прогресс-бар и пульс. Формат менять
  нельзя: это контракт GUI-CLI.
- Коллбэк строки (`on_line`) обёрнут в try/except: сбой обработчика
  конкретной строки не хоронит весь поток чтения, ошибка идёт в журнал.
- «Занято» защита: один прогон за раз, кнопки родственной группы
  блокируются на время.

## 6. Журнал

- `CTkTextbox` в общей теме (скроллбар, скругление), моноширинный шрифт,
  теги цветов: err/ok/warn/found (подсветка поиска).
- Умный автоскролл: следует за выводом только когда пользователь стоит
  у низа (`yview()[1] > 0.998`); прокрутка вверх останавливает «следить»,
  прокрутка обратно вниз включает. Триггеры отслеживания: Configure,
  MouseWheel, кнопки прокрутки, клавиши, с отложенным вызовом `after(10)`.
- Инструменты в панели журнала: поиск с подсветкой (Enter, Esc сброс),
  «Очистить», «Копировать всё», масштаб шрифта А-/А+ (сохранение размера
  в конфиг).
- Методы tk.Text, не завёрнутые в CTkTextbox, делегируются напрямую:
  `self.log.search = inner.search`, `self.log.tag_configure = self.log.tag_config`.

## 7. Темы

- Переключатель light/dark в шапке, выбор пишется в конфиг,
  `ctk.set_appearance_mode` глобально плюс точечная перекраска
  нестандартных виджетов журнала (`fg_color`, `text_color`,
  `insertbackground`).
- Цветовые константы (акцент, опасность, ок, предупреждение) задаются
  парами «(цвет для светлой, цвет для тёмной)».

## 8. Горячие клавиши

- Ctrl+1/2/3: переход по вкладкам (`bind_all`, цифры не мешают набору).
- Ctrl+S: сохранение конфига.

## 9. Настройки и конфиг

- Правило конфиг-UI: каждая настройка существует в трёх местах:
  контрол на форме, чтение в `_load_cfg`, запись в `_collect_cfg`.
  Новая опция добавляется во все три сразу, иначе «нажал, а не применилось».
- Исправленные раньше ловушки: None в цветовых параметрах
  (`border_color`/`text_color`, равные None, у CTk дают ValueError,
  поэтому подсветку цветов добавляют через заглушку вроде
  `border_width=0`); гарантированное создание секций конфига перед
  использованием (`setdefault`); восстановление значений с проверкой
  типа.
- Подсказки Tooltip на каждом управляющем элементе: краткое описание
  эффекта, не только названия.
- Карточки (`_card`): заголовок + внутренняя рамка; размещения по сетке
  с паддингом 10 и ровной вертикальной шкалой (pady 4, отступ заголовков).

## 10. Приёмы проверки (автотесты)

- Тест «кнопок»: рекурсивный сбор всех `CTkButton` (вкладки и все
  подокна), проверка, что `command` не None; безопасные кнопки реально
  кликаются, опасные (запись/удаление) ограничиваются проверкой привязки.
- Тест «вкладки»: переключение сегментов и вкладок, синхронизация,
  история путей, горячие клавиши через `event_generate`.
- Тест «подокна»: открытие каждого инструмента, проверка кнопок,
  уничтожение без следов.
- Любой тест с конфигом: байт-в-байт откат реального конфига в конце
  (тесты пишут мусор, конфиг пользователя не трогается).
